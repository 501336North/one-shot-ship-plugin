## Part K1 — fail-open, git calls, work budget (agent 1)

Acceptance: `git clean -fdx $D` with untracked `.oss/tool-gates/` refused; `git clean -f $X; git push --force origin main` refused.
2. **HIGH: per-call work budget.** Inputs within the caps push the decision past the timer → allow: (a) 150-300 `git commit -qm x;` parts then `git push origin HEAD:main` (one `git symbolic-ref` per part); (b) a `git clean` dry run listing ~30k files (each line resolved on disk); (c) a symlink whose target has ~400 names (`x/../x/../…`) used in ~35 words 41 links deep (`path-resolver.ts` MAX_LINKS caps links, not names; `formsOf` resolves twice). Fix: cache `currentBranch` per folder and memoise resolved paths for the call; cap git runs per call (e.g. 8 distinct) and fs lookups per call (e.g. ~20k readlink/lstat); cap dry-run lines (e.g. 2048) → treat as "git can't tell" and use the fallback; compare dry-run lines as text against the fixed protected folders instead of a disk walk per line where possible. ## Part K2 — command reading (agent 2, after K1)
5. **HIGH: fake toplevel.** `toplevelOf` takes any folder with a `.git` entry; git skips an invalid `.git`. After `mkdir -p sub/.git`, `cd sub && cd "$(git rev-parse --show-toplevel)" && echo x > .claude/settings.json` writes the real root. Fix: only accept the toplevel cd when the gate can be sure where git lands (e.g. the nearest valid `.git` is the project root's, validated like git does: HEAD file + objects/refs, or a `.git` file whose gitdir is valid); otherwise the folder is lost.
6. **HIGH (user pick, gap 2): relative writes after a lost `cd`** are allowed today (`cd "$X" && echo x > .oss/workflow-state.json`, `cd ${X:-.oss} && rm workflow-state.json`). Fix: after a lost folder, a relative write target is refused when it could be a protected path under some root (match the protected patterns against the relative path as a tail, and treat the lost folder as possibly any protected folder, e.g. `rm workflow-state.json` after a lost cd whose known text mentions `.oss`). Keep ordinary `cd "$X" && echo x > out.txt` / `npm test` allowed. If the only way to close it refuses ordinary commands, report the trade-off instead.
7. **HIGH: `git clean -fdx -n --no-dry-run`** is read as a dry run. Fix: last of `-n/--dry-run/--no-dry-run` wins (and `-f` counts). **MEDIUM:** earlier parts of the same call that untrack files (`git rm --cached`, `read-tree`, `reset`, `checkout --orphan`, `update-index`, `stash`, `restore --staged`, `switch --orphan`…) make the dry run stale → if any earlier part could change the index/HEAD, use the text fallback. **LOW:** `-ff` dropped from the dry run → keep the doubled f so nested repos are listed.
8. **MEDIUM: sed/awk scripts** that write a named protected file are allowed (`sed -n 'w .oss/tool-gates.json' a`, `sed 's/a/b/w .oss/…'`, `sed '1e cp …'`, `awk 'BEGIN{print > ".oss/…"}'`, `awk 'BEGIN{system("cp …")}'`) and shortened in-place forms (`sed --in-pl`, `--in`, `gawk --inc inplace`, `gawk -l inplace`, `@include "inplace"`). Fix: sed/awk stay read-only for their FILE operands only; their script text is checked like an interpreter literal (protected name in the script → refused; `e`/`system(` with anything → treat script as a shell script); any unambiguous prefix of `--in-place`/`--include`/`--load`, `-l`, `@include`/`@load` → writer. `sed -n 1,5p .oss/tool-gates.json` and `jq`/`awk '{print $1}' .oss/workflow-state.json` stay allowed.
9. **MEDIUM:** `git checkout -b feat; git commit` and `checkout -b feat || git commit` from main are allowed. Fix: the new-branch exception applies only when the checkout/switch and the commit/push are joined by `&&` all the way. **LOW:** `git checkout -b X origin/main && git push` (bare push) can push to main with `push.default=upstream` → the exception for push requires the push to name X explicitly as the destination, or no start point / a local start point.
10. **MEDIUM (GNU):** cp/mv/ln/install backups: with `-b`/`--backup[=…]`, the backup name (`dest` + `--suffix`/`-S` value, default `~`, `SIMPLE_BACKUP_SUFFIX`, numbered `.~N~`) is also a write target and is checked.
11. **(user pick, gap 1)** `git checkout main && git commit` / `git switch main && git commit` in one call: track branch switches within the call; after a checkout/switch to a protected branch (or an unknown one, `-`, `@{-1}`, `$X`), a later commit/push in that folder is refused.
12. **(gap 8)** `git update-ref refs/heads/<protected> …`, `git branch -f|-M|-m|-C|-c <…> <protected>`, `git branch -D/-d <protected>`, `git symbolic-ref HEAD refs/heads/<protected>` move or change a protected branch → refused (the rule id protected-branch). Ordinary `git branch feat`, `git branch -d feat-old` stay allowed.
13. **(gap 3)** writes to `.git/hooks/*` (and `core.hooksPath` changes already? check) → protect `**/.git/hooks/**` in config (update the provenance pin). Reads stay allowed.
14. **(gap 4)** `python3 < script.py`, `node < x.js`, `bash < x.sh`, `echo … | python3`, `cat x | sh`: an interpreter whose script comes from stdin. A literal piped `echo`/`printf` text is read as the script; a file redirect or unknown pipe source is unreadable → refused under ADR-010 (risky: interpreter). `python3 script.py` and `node x.js` (script file as argument) keep today's behaviour.
15. **(gap 5)** `ditto` (macOS) writes its last operand → add to the writers like `cp -r`.
16. **(gap 6)** `shopt -s dotglob`, `setopt globdots`/`GLOB_DOTS`, `setopt extendedglob` with `(D)` qualifier: after these in the call, `*`/`?` globs also match dot entries (so `rm -rf *` at the root reaches `.oss`). Also zsh `**` — check the R2b note and fix in whichever direction is correct.
