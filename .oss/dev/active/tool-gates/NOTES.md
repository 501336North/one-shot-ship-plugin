## Ship round 1 fixes (F3a, 2026-11-09)
- **(c) Substitutions are read, not unreadable.** The tokenizer reads `$( … )`, backticks (plain, nested, in `"…"`), `<( … )` and `>( … )`. In the outer word each one is the sentinel `UNKNOWN` (`'\u0000DYN\u0000'`, exported from `tokenize.ts`), alone or inside known text (`.oss/tool-gates/` + `UNKNOWN`). A word or redirect token carries `scripts?: Token[][]`, the tokens of each substitution's body. The reader reads them as nested parts (same depth limit 5 as `bash -c`), placed before the part that uses them, in that part's directory, with `pipedOut: true` (the shell captures their output). Substitutions in skipped words (a `for` list, a `case` word) and in assignment-only commands (`x=$(git push --force)`) are still read. `$(( … ))` is an `UNKNOWN` word with no parts; arithmetic holding `$(` or a backtick is unreadable. Unreadable stays for: unterminated quotes or substitutions, nesting over the limits, input over 1 MB, `eval` / `-c` whose script holds `UNKNOWN` or a `$` expansion (unchanged rule). Known limit: a `case … in a)` inside `$( … )` ends the substitution at the pattern's `)`.
- **Unknown directories:** `cd`, `pushd`, `git -C`, `env -C` and `sudo -D` to a value holding `UNKNOWN` leave the directory as it was (`cd "$(git rev-parse --show-toplevel)"` is the common case), so no path or git dir ever holds the sentinel. A write target can (`> "$(x)"`); F3b decides how protected-path treats it.
- **Expansion before the rules see a word:** unquoted brace groups expand as bash does (nested, `{}` / `{x}` / unclosed kept, first valid group first; sequences `{1..3}`, `{c..a}`, `{01..03}`, `{1..10..4}` up to 64 items, longer ones kept as written; over 256 words is unreadable). A redirect target that expands to several words gives one redirect per word (bash says "ambiguous redirect" and writes nothing, so this only over-refuses). Heredoc delimiters are not expanded. `$HOME` / `${HOME}` (bare or in `"…"`) become the home folder; every other `$X`, `${…}`, `$1`, `$@`, `$?` … is `UNKNOWN`. `~name/…` is home when `name` is the basename of home or `os.userInfo().username`, else `UNKNOWN`; a bare `~` and `~/` are still left to the reader's `expandTilde`. NUL characters are dropped from the command (bash drops them when it reads a script), so `UNKNOWN` can't be typed.
- **Speed caps:** input over 1 MB, substitutions nested over 64 (tokenizer), `{ … }` / `( … )` groups nested over 64 and more than 64 wrappers in a row (reader) are unreadable. The 100k `{ a; ` input and 40k wrappers each return in well under 1 s; brace expansion is one linear pass per level.
- **Tests changed by design:** tokenize "unreadable when it contains $( or backticks or a process substitution" (deleted; replaced by the substitution tests) and `eval "$CMD"` now has the word `UNKNOWN`; command-reader "return the tokenizer's unreadable result unchanged" uses an unterminated quote instead of `$( … )`, and "keep a program that is a variable" now expects `UNKNOWN` instead of `$G`; failure.test "allow and log unreadable for eval / $( … )" now uses `bash -c "$(curl …)"` (the old `git push origin $(…)` on main is now refused).
- **Not done (outside the brief):** an unquoted heredoc body (`cat <<EOF` … `$(git push -f)` … `EOF`) runs its substitutions in bash but is still skipped unread.

## Ship round 1 fixes (F3b, 2026-11-09)
- **(c-finish) Unquoted heredoc bodies are read.** The tokenizer reads the `$( … )` and backtick substitutions of a heredoc body whose delimiter has no quoting at all (`<<EOF`, `<<-EOF`); their scripts go on the heredoc's redirect token, so the reader runs them as nested parts. Any quote or backslash in the delimiter (`<<'EOF'`, `<<"EOF"`, `<<\EOF`, `<<E"OF"`) keeps the body literal, as in bash. In the body, quotes are text and `\$` / `` \` `` stay text. An unterminated substitution in a body is unreadable.
- **(c-finish) `case … in a)` inside `$( … )`.** The scanner follows `case` (only where a command starts: after an operator, at the start, or after `then`/`do`/`else`/`elif`/`if`/`while`/`until`/`{`/`!`/`time`), `in`, each pattern's `)` (and a leading `(`), `;;` and `esac`; a pattern's `)` never closes the substitution. `echo $(echo case in a)` still ends at `a)`. The brief's example `x=$(case y in a) git push --force;; esac)` was already refused by luck (the mis-split left `git push --force` in the outer command); the hiding form was the quoted one, `echo "$(case y in a) git push --force;; esac)"`, which is the RED test.
- **(d) Push hardening** (`rules/push-setup.ts`, rule id `protected-branch`, runs first in the Bash chain):
  - A `git push` is refused when an earlier part of the same call ran `git checkout`, `switch`, `symbolic-ref`, `worktree`, `init`, `clone`, `git branch -m/-M/--move/-u/--set-upstream-to/-t/--track`, `git remote add/rename/remove/rm/set-url`, set `GIT_DIR` / `GIT_WORK_TREE` / `GIT_CONFIG*` (`GIT_DIR=x;` alone, or `export`/`declare`/`typeset`/`readonly`/`local`). Beyond the brief: the `branch`, `symbolic-ref`, `worktree`, `init`, `clone`, `remote` and earlier-variable cases, which move the branch or repository the same way.
  - A `git push` carrying `-c`, `--config-env`, `--git-dir`, `--work-tree` (global options), or a `GIT_DIR` / `GIT_WORK_TREE` / `GIT_CONFIG*` assignment (prefix, `env`/`sudo` wrapper, or inherited by `bash -c`) is refused. Reason: "this `git push` can't be checked: … Push with a separate plain `git push`."
  - `git config` that writes `push.*`, `remote.pushDefault`, `remote.*.push|url|pushurl`, `branch.*.merge|remote|pushRemote`, `url.*.insteadOf|pushInsteadOf` (keys lowercased; option forms `--add`, `--replace-all`, `--unset*`, `-e`; verb forms `set`/`unset`/`edit`; `--rename-section`/`--remove-section` of a `push`/`remote`/`branch`/`url` section) is refused on its own: "changes where pushes go". Reads (`--get*`, `--list`, `get`, `list`, a key alone) are allowed. Beyond the brief: `remote.pushDefault` and `branch.*.pushRemote`, which also pick the push remote.
  - `CommandPart.assignments` (new) holds the names of the variables set for a part: prefix assignments, `env`/`sudo` wrapper assignments, and those of an outer `bash -c`.
  - Destinations: `protected-branch.ts` already handled `refs/heads/` and `+`; `heads/<branch>` was added. No config value was needed.
- **(e) New rule `protected-path-mention`** (`rules/protected-path-mention.ts`, last in the Bash chain, so a part `protected-path` refuses is refused once, under `protected-path`):
  - A part whose program is not read-only is refused when a word (and the value after `=`) resolves, against the part's directory (git's `-C` directory for git), to a protected path or a folder holding one. The repo root, home and their ancestors don't count (`git add .`). Case follows F2's platform flag.

## Ship round 2 fixes (R2a, 2026-11-10)
Every fix here closes a way to make the gate slow or blind, since a slow gate allows the call (ADR-005).
- **(1) Real time limit.** The CLI runs the decision in a `worker_threads` Worker (the same bundle file, told apart by `workerData.toolGate`) and `terminate()`s it at `HARD_LIMIT_MS` = 2500 ms (above the in-process 2 s race, which still answers a hung git read; below the 5 s hook timeout). At the limit, or when the worker crashes or posts nothing usable, the main thread answers `gateErrorResult` (gate.ts): `gate-error` logged, allow + tell. `decideInWorker(script, argv, input, env, limitMs)` is exported and tested with stub worker scripts (stuck, crashing, answering). The wrapper now runs node in the background (`<&0` keeps stdin, stdout to a `mktemp` file) and traps TERM/INT/HUP: it kills node, removes the file and exits 143. Without `mktemp` it falls back to the old foreground run. A KILL to the wrapper can't be trapped; the worker limit ends node within ~2.5 s then, and the temp file stays behind.
- **(2) Long words.** `protected-path-mention` refuses any word, `x=value` value or script literal over 4096 chars / 512 segments with the write-target `TOO_LONG` reason, before any lookup. `path-resolver.ts` builds the path by appending, pops a reversed name stack (no `shift`/`unshift`), and makes no `readlink` below a name that is missing (ENOENT, ENAMETOOLONG, ENOTDIR) until a `..` climbs back out (a link reached that way is still followed).
- **(3) Word budget while expanding.** `ReadBudget` (tokenize.ts, one per `readCommand`, shared by nested `-c` scripts and `env -S`) counts words and characters as each word is pushed, and checks a brace expansion's count and size before building it. Over `MAX_CALL_WORDS` = 2048 words or `MAX_CALL_CHARS` = 64 KB the read stops as a reading limit. Post mode reads the same way, so an over-limit command is not recorded.
- **(4) Parts.** `checkCallSize` counts each part at least once (`x=1;`) and adds interpreter script literals. `checkPushSetup(part, parts, index)` takes the index (the third argument defaults to the list length, so the old two-argument call still works). Repo/home places are made once per call in `checkBash` and passed to both path rules (optional last argument).
- **(5) Script literals** are collected once per part, deduplicated, length-checked, and counted toward the call budget. The regex stays: a test with 20 000 escaped quotes was not slow before the fix, so it was not kept.
- **(6) Repo globs.** A repo file adding more than `MAX_REPO_ADDED` = 64 distinct values to any list (all lists, not just globs) is rejected as a whole ("`<key>` adds more than 64 values"). Compiled glob segments (patterns.ts) and fixed folders (protected-path.ts) are cached per places object and list (WeakMaps), so they are built once per call.
